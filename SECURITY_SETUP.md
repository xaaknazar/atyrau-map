# Защита данных — план внедрения (серверная модель доступа)

Текущая проблема: приложение полностью клиентское, пароли и ссылки на Google Sheets
были в браузере/публичном репозитории — это обходится через консоль. Ниже — переход
на серверную защиту. Внедряется поэтапно, чтобы не сломать рабочий сайт.

## Что уже добавлено в код (Этап 1)
- `api/_auth.js` — подписанная сессия-cookie (HMAC), проверка доступа `requireAuth`.
- `api/login.js` / `api/logout.js` / `api/me.js` — вход/выход/проверка сессии.
- `api/data.js` — защищённый прокси: сервер сам читает таблицы, браузер не получает прямых ссылок.
- Защита `api/ai-analyze.js` и `api/check-registration.js` (за флагом `AUTH_ENFORCE`).

Флаг `AUTH_ENFORCE` по умолчанию ВЫКЛЮЧЕН — сайт работает как раньше, пока не завершите настройку.

---

## Шаг 1 — СРОЧНО (бесплатно, сделать сегодня)
1. Сделать GitHub‑репозиторий **приватным**: GitHub → Settings → General → Danger Zone → Change visibility → Private.
2. **Сменить все пароли** (текущие скомпрометированы — были в публичном репо).
3. В консоли Firebase закрыть правила Realtime Database (см. Шаг 5).

## Шаг 2 — Переменные окружения в Vercel
Vercel → проект `atyrau-map` → Settings → Environment Variables. Добавить:
```
SESSION_SECRET        = <длинная случайная строка, 40+ символов>
APP_PASSWORD_STAFF    = <новый пароль сотрудника>
APP_PASSWORD_ADMIN    = <новый пароль администратора>   (необязательно)
APP_PASSWORD_AKIMAT   = <новый пароль акимата>           (необязательно)
DATA_SHEET_ID         = 1W7J6c7rM3Skd5cJbv_95J3d5fM_6X5mBNQBvhxhLkBU
CRIMES_API_URL        = <URL вашего Apps Script для ЕРДР>
# AUTH_ENFORCE        = 1   ← включить ТОЛЬКО после Шага 3 (миграции клиента)
```
После добавления — сделать Redeploy.

## Шаг 3 — Миграция клиента на прокси (делаю я, отдельным пушем)
Переписать загрузчики (`crimes.js`, `admin-violations.js`, `cameras.js`, `police.js`,
`schools.js`, `venues.js`, `alkomarkets.js`) так, чтобы они брали данные из `/api/data?source=…`
(с `credentials: "include"`), а не напрямую из Google. Заменить фальшивый вход (`1345`) на
реальную форму, вызывающую `/api/login`. После этого ссылки на таблицы исчезают из браузера.

## Шаг 4 — Приватные таблицы + сервисный аккаунт (полная защита)
Пока таблицы открыты «по ссылке», их можно достать, зная id. Чтобы закрыть окончательно:
1. Создать сервисный аккаунт в Google Cloud, скачать JSON‑ключ.
2. Открыть каждую таблицу только для email этого сервисного аккаунта (Share → только он).
3. Убрать общий доступ «по ссылке».
4. Добавить env `GOOGLE_SERVICE_ACCOUNT_JSON = <содержимое ключа>`.
5. Я обновлю `api/data.js`, чтобы читал через Sheets API от имени сервисного аккаунта.
После этого прямой доступ к таблицам из браузера/по ссылке невозможен — только через вход.

## Шаг 5 — Правила Firebase Realtime Database
Firebase Console → Realtime Database → Rules. Не оставлять `".read": true, ".write": true`.
Минимум — ограничить запись и чувствительные узлы. Идеально — вынести чтение/запись
чувствительных данных за серверные функции (как с таблицами) либо включить Firebase Auth.

## Шаг 6 — Включить защиту
Когда Шаги 2–3 выполнены и проверены: выставить `AUTH_ENFORCE=1` и сделать Redeploy.
Теперь без входа `/api/data` и `/api/*` возвращают 401, а данные нельзя достать через консоль.

---

### Проверка после включения
- Открыть сайт в приватном окне без входа → данные не загружаются, требуется пароль.
- DevTools → Network → нет прямых ссылок на docs.google.com в клиенте.
- Прямой запрос `/api/data?source=admin` без cookie → 401.
- Прямой запрос к таблице по id (после Шага 4) → доступ запрещён Google.
