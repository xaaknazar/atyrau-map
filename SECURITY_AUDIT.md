## Находки по критичности

### 🔴 Критично

1. **Публичный доступ к ПДн без аутентификации.** Google-таблица открыта по ссылке;
   id таблицы и прямые CSV-ссылки зашиты в клиентском JS
   (`crimes.js`, `admin-violations.js`, `venues.js`, `police.js`, `cameras.js`,
   `schools.js`, `alkomarkets.js`). Любой может открыть исходник страницы и скачать всё.

2. **`/api/crimes` — публичный.** Отдаёт преступления и данные лиц без сессии.
   Проверено: 200 OK, keys `crimes, people`.

3. **Фейковый вход в браузере.** В `index.html` зашит `AUTH_HASH = "1345"` (виден в
   исходнике). Данные грузятся всё равно, независимо от «входа». Защита нулевая.

4. **`AUTH_ENFORCE` выключен (по умолчанию).** Пока флаг не равен `1`, серверные
   эндпоинты `/api/data`, `/api/ai-analyze`, `/api/check-registration` открыты всем.
   Это значит: (а) чужие могут гонять ваш ключ OpenAI (расход денег/злоупотребление),
   (б) `/api/data?source=people` отдаёт ПДн без входа. — *Проверить факт значения флага
   в Vercel; по коду и SECURITY_SETUP.md он не включён.*

### 🟠 Высокий

5. **Firebase Realtime Database, вероятно, в «test mode»** (по комментариям в коде и
   плану внедрения — `".read": true, ".write": true`). Тогда любой может читать и
   **перезаписывать** узлы `points` (точки карты) и `regCheckAI` (результаты AI-проверок).
   — *Нужно проверить правила в консоли Firebase.*

6. **Apps Script теперь «Anyone».** Мы открыли его, чтобы починить Safari — значит
   JSON преступлений+лиц доступен и напрямую по URL скрипта. Это допустимо **только**
   за приватным прокси с входом; сейчас прокси тоже публичный.

7. **Репозиторий GitHub, вероятно, публичный** (в прежнем плане прямо сказано, что
   ссылки и пароли «были в публичном репозитории»). Старые пароли могут оставаться в
   истории коммитов. — *Проверить видимость репо и историю.*

### 🟡 Средний / низкий

8. Нет `.gitignore` — риск случайно закоммитить секреты в будущем.
9. Нет ограничения частоты запросов (rate limit) на AI-эндпоинтах.
10. Токен доступа GitHub (PAT) фигурировал в рабочей среде — для перестраховки заменить.

Фундамент заложен верно — не хватает «последней мили»: подключить клиент к прокси,
закрыть таблицы и включить принуждение входа.

## Ключевое решение

Нельзя одновременно «карта открыта всем без входа» и «ПДн защищены». Нужно выбрать:

- **Приватная карта (рекомендуется для ПДн):** вход обязателен для всех, данные только
  через авторизованный прокси. Safari-пользователи тоже входят по паролю.
- **Публичная карта:** тогда из неё нужно **полностью убрать персональные данные**
  (лист «Люди», описания/адреса по лицам), оставить только обезличенную статистику.

Учитывая, что это криминальные данные и данные несовершеннолетних — по умолчанию
следует делать приватную.

## План устранения (по приоритету)

**Сегодня (срочно, бесплатно):**
1. Сменить пароль(и) — `1345` и любые прежние считать скомпрометированными.
2. Сделать GitHub-репозиторий приватным; проверить историю на пароли/ключи.
3. Firebase → Realtime Database → Rules: убрать `".read/.write": true`. Минимум —
   закрыть запись и чувствительные узлы.

**На этой неделе (закрыть утечку ПДн):**
4. Подключить клиент к `/api/data?source=…` (с `credentials:"include"`) вместо прямых
   ссылок на Google — убрать id таблицы и CSV-URL из браузера. Затронуть все загрузчики
   и `/api/crimes` (завести под ту же авторизацию).
5. Заменить фейковый `AUTH_HASH="1345"` на реальную форму входа через `/api/login`.
6. Прописать env в Vercel (`SESSION_SECRET`, `APP_PASSWORD_*`, `DATA_SHEET_ID`,
   `CRIMES_API_URL`) и включить **`AUTH_ENFORCE=1`**.

**Полная защита (чтобы таблицу нельзя было достать даже по id):**
7. Создать сервисный аккаунт Google, открыть таблицы только ему, убрать доступ «по
   ссылке» и публикацию в интернет. Читать через Sheets API от имени сервисного
   аккаунта в `api/data.js`. Аналогично закрыть Apps Script (Execute as Me, доступ —
   только сервисный аккаунт/после входа).

**Проверка после включения:**
- Приватное окно без входа → данные не грузятся, просит пароль.
- DevTools → Network → нет запросов к `docs.google.com` / `script.google.com` из браузера.
- `/api/data?source=people` и `/api/crimes` без cookie → 401.
- Прямой запрос к таблице по id → Google отвечает «нет доступа».
